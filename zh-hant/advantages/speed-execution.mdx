Owly 將策略操作提交給 Hyperliquid，並在執行結果可用時更新帳戶狀態。複製決策、交易所接受、成交和組合更新是不同階段。

## 影響執行的因素

| 階段 | 影響因素 |
| --- | --- |
| **觀察來源** | 資料時效和來源市場活動 |
| **策略決策** | 帳戶狀態、跟單比例、啟用交易所、幣種過濾和風險設定 |
| **提交委託** | 授權有效期、最低委託額、抵押品和交易所規則 |
| **成交** | 訂單類型、價格、流動性、部分成交和行情變化 |
| **介面更新** | WebSocket 連線、API 可用性及快取或重新整理資料 |

提交後，委託可能保持掛單、部分成交或被拒絕。啟動請求成功不代表來源的全部倉位已經複製完成。

## 複製與同步

跟單設定包含定期倉位、現貨、槓桿和可選的掛單同步，各自有啟用狀態及時間間隔。同步週期不等於端到端執行保證；LeverAcc 不支援複製掛單。

網格機器人按自己的週期校準網格，其行為及帳戶條件見[網格機器人](/zh-hant/guide/grid-bot)。

## 核對結果

1. 檢查機器人當前狀態及錯誤資訊。
2. 檢視實際委託和成交，包括部分成交或拒單。
3. 比較來源前先確認市場和帳戶統計範圍一致。
4. 停止或關閉後，檢查剩餘委託、持倉和清理狀態。

當前實現不能提供固定延遲或滑點保證，結果受行情和上游服務可用性影響。執行與預期不符時，參見[故障排除](/zh-hant/faq/troubleshooting)。

團隊的非同步 Hyperliquid SDK 見 [async-hyperliquid](https://github.com/owlyfi/async-hyperliquid)。SDK 基準只說明特定測試條件，不能當作使用者交易的延遲承諾。
