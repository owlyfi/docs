# Owlyfi 邀請分傭系統

分享邀請碼或邀請連結，邀請好友使用 Owly。好友通過納入結算的交易帳戶產生 Builder 手續費後，你可以獲得直接（L1）返佣；好友邀請的使用者還可以為你帶來間接（L2）返佣。被邀請使用者可按適用規則享有一段時間的平臺交易手續費折扣。

## 兩級邀請關係

假設 A 邀請 B，B 再邀請 C：

| 產生手續費的使用者 | 返佣接收者 | 計算比例 |
| :--- | :--- | :--- |
| B | A，獲得 L1 返佣 | A 所在等級的 L1 比例 |
| C | B，獲得 L1 返佣 | B 所在等級的 L1 比例 |
| C | A，獲得 L2 返佣 | A 所在等級的 L2 比例 |

系統只結算 L1 和 L2 兩級返佣。每位接收者使用自己的適用等級比例，C 符合條件時享有的手續費減免統一為 5%，不區分直接邀請人 B 的等級。

## 等級與返佣結構

邀請系統支援 Normal、Advanced 和 VIP 等級。以下為預設規則，實際生效值可由平臺配置調整：

| 等級 | 直接邀請累計手續費門檻 | L1 返佣 | L2 返佣 | 好友手續費減免 | 折扣期限 | 直接邀請名額 |
| :--- | :--- | :--- | :--- | :--- | :--- | :--- |
| Normal | $0 | 30% | 2% | 5% | 14 天 | 5 人 |
| Advanced | $10 | 35% | 3% | 5% | 14 天 | 20 人 |
| VIP | $500 | 40% | 5% | 5% | 14 天 | 不限 |

<Note>
表中的折扣期限和邀請名額為預設配置，實際生效值可由平臺配置調整。請在**邀請分傭**頁面檢視自己的當前等級、邀請名額、可提現獎勵和返佣記錄。
</Note>

自動等級評估依據**已啟用的直接邀請使用者（L1）在返佣記錄中累計的 Builder 手續費**，不包含 L2 手續費，也不按交易量或邀請人數評定。系統在結算後重新評估等級，後續結算使用更新後的適用比例；已結算獎勵不會因升檔自動重算。部分帳戶可能適用平臺指定等級或單獨調整的邀請名額。

直接邀請關係繫結後即佔用邀請名額，尚未交易的好友也計入；間接邀請不佔用你的直接邀請名額。

## 返佣計算基數

平臺 Builder 手續費隨策略而不同，策略基礎費率為 **2–10 bps（0.02%–0.1%）**，具體以所選策略的 Builder 費率配置為準。相同交易量在不同策略下可能產生不同的手續費和返佣金額；符合條件的邀請折扣也會影響實際手續費。

返佣按**納入結算的成交記錄中實際收取的 Builder 手續費 × 接收者適用的返佣比例**計算。手續費基數來自被邀請使用者當前有效、納入結算的交易子帳戶；不能將其錢包在其他帳戶或平臺上的全部交易視為可返佣交易。

好友支付的手續費降低後，返佣基數也會隨之降低。Hyperliquid 交易所手續費、資金費和網路費用不屬於該 Builder 手續費基數。

## 好友折扣說明

繫結邀請關係時，系統按直接邀請人的適用等級規則確定折扣到期時間，並從**繫結時刻**開始計時，無需等待首次交易。預設期限為 14 天，實際以繫結時適用配置為準。該折扣期限與瀏覽器儲存邀請碼的歸因期限是兩回事。

- 折扣期內，符合條件且由 Owly 管理費率的策略可以自動應用較低的 Builder 手續費。
- 所有標準邀請人等級均統一減免**適用 Builder 手續費的 5%**，不會因邀請人升檔而提高減免比例。
- 邀請人升檔不會自動延長已確定的折扣到期時間；折扣到期本身也不會解除邀請關係或終止返佣。
- 折扣通過減少交易時收取的費用體現，不會生成一筆需要好友單獨提現的現金返還。
- 使用第三方 Builder 或保留獨立低費率的策略不會被統一折扣規則覆蓋，請在交易前確認實際費率。

折扣按所選策略的適用基礎費率計算。例如，假設某策略的基礎 Builder 費率為 **5.5 bps（0.055%）**，好友手續費減免為 5%，則折扣後的理論費率為 `5.5 × (1 − 5%) = 5.225 bps`。此處的 5.5 bps 僅為示例，實際策略基礎費率在 2–10 bps 範圍內，取決於具體策略配置。實際訂單費率還會按交易介面支援的精度向上取整，返佣始終以實際成交手續費為準。

有關實際交易費與 Builder 授權上限的區別，請參閱[費用結構](/zh-hant/faq/fees)。

## 邀請歸因邏輯

Owly 在註冊前採用**同一瀏覽器內的首次接觸歸因**：

1. 訪問邀請碼格式有效的邀請連結後，首個邀請碼儲存在瀏覽器 Cookie 中，最長保留 **30 天**。邀請碼是否存在及是否仍有名額，在註冊或繫結時校驗。
2. 該 Cookie 有效期間，後續邀請連結不會覆蓋它；已登入使用者訪問邀請連結也不會更換現有邀請人。
3. 註冊時嘗試使用儲存的邀請碼。後臺會校驗邀請碼及剩餘名額；攜帶無效或已滿額邀請碼的請求會被拒絕。當前頁面在自動使用邀請碼失敗後會提示錯誤，並嘗試不帶邀請碼繼續註冊；註冊成功不等於邀請關係已繫結，可在邀請分傭頁面確認邀請人。

Cookie 不等於永久帳戶繫結：清除 Cookie、到期或更換瀏覽器、裝置後，原先儲存的歸因可能丟失。帳戶一旦已有邀請人，普通繫結流程不允許更換；如果註冊時沒有繫結邀請人，符合條件的使用者可以在邀請分傭頁面補填一次邀請碼。

邀請碼由 **4–16 位字母、數字、下劃線或連字元**組成，匹配時不區分大小寫。繫結還需通過邀請碼有效性、剩餘邀請名額和邀請資格檢查。

## 結算與提現

系統通過定時任務拉取符合條件的成交手續費，按各交易子帳戶尚未結算的區間計算獎勵。成功結算時，獎勵記錄與可用返佣餘額一併更新；同一已成功結算區間不會因任務重試重複發放。

結算會預留資料同步延遲，記錄出現的時間受任務排程、帳戶結算狀態和上游資料可用性影響。成交後不會立即生成可提現返佣，介面暫時失敗時需等待後續成功結算。

邀請關係可能先處於 `pending` 狀態，待記錄到符合條件且產生手續費的交易活動後再啟用。邀請分傭頁面分別展示邀請使用者、已交易使用者、返佣記錄和提現歷史。

### 歷史交易與結算時間

- 新交易帳戶首次納入結算時會先建立結算起點，不會自動補發此前全部歷史交易的返佣。補綁邀請碼也不代表既往交易一定可追溯返佣。
- 處於待對帳狀態的歷史帳戶，需要先完成對帳才能繼續結算；相關歷史獎勵不會自動補發。
- 返佣記錄中的**結算時間**是獎勵實際結算入帳的時間。結算日期是任務的記帳日期，不能據此認定全部手續費都發生在該日，也不能將記錄建立時間當作結算時間；歷史記錄缺少結算時間時以頁面顯示為準。

### 如何提現

1. 開啟**邀請分傭**頁面，檢視可提現返佣餘額。
2. 輸入不超過該餘額的金額。當前提現表單要求至少 **1 USDC**，實際適用規則可能要求更高的最低金額。
3. 提交申請。申請金額會先從可用返佣餘額中扣除，進入後續處理流程。
4. 在提現歷史中跟蹤結果，核對最終狀態和交易憑證。

| 狀態 | 含義 |
| :--- | :--- |
| `pending` | 已提交，等待稽核 |
| `approved` | 已批准，等待處理 |
| `processing` | 正在處理 |
| `completed` | 已記錄為完成，並附有交易憑證 |
| `rejected` / `failed` | 稽核拒絕或處理失敗，申請金額退回可用返佣餘額；原因見記錄詳情 |

<Note>
提交申請不等於立即完成鏈上轉帳。請以提現記錄確認結果，本文不承諾固定到帳時間。
</Note>

## 分傭計算示例

假設 A、B 均適用 Normal 預設比例，A 邀請 B，B 邀請 C。本例假設策略的**實際成交 Builder 費率為 5.5 bps（0.055%）**，即已考慮適用折扣及費率取整後的實際費率：

1. B 成交 10,000 USDC，實際 Builder 手續費為 `10,000 × 0.055% = 5.50 USDC`，A 獲得 L1 返佣：`5.50 × 30% = 1.65 USDC`。
2. C 成交 20,000 USDC，實際 Builder 手續費為 `20,000 × 0.055% = 11.00 USDC`，B 獲得 L1 返佣：`11.00 × 30% = 3.30 USDC`；A 獲得 L2 返佣：`11.00 × 2% = 0.22 USDC`。
3. A 本次合計獲得 `1.65 + 0.22 = 1.87 USDC`。C 的同一筆手續費分別作為 B 的 L1 和 A 的 L2 計算基數。

5.5 bps 是本例假設的費率，不代表所有策略統一收取該費率；示例返佣比例也不代表當前等級規則。實際金額請以適用規則和已結算返佣記錄為準。

## 參與條件

系統拒絕自我邀請和迴圈邀請關係。邀請碼也受使用次數限制，除非適用等級或帳戶名額另有安排。請勿使用虛假帳戶或人為製造的活動繞過邀請規則。
