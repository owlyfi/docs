Open **Trading Bots → Grid Trading** at [Grid Trading](https://app.owly.fi/trading-bots/grid). Sign in before managing bots.

## Current support

The grid editor supports perpetual markets, **Neutral**, **Long**, and **Short** directions, **Arithmetic** or **Geometric** spacing, and **Cross** or **Isolated** margin. It also exposes a trigger price, directional initial positions, and strategy take-profit and stop-loss prices.

<Note>
Spot grid is not available in this editor. Upward and downward trailing controls are visible but disabled. The Grid option in the separate [Trade terminal](/guide/trading-terminal) is also a preview; use the Grid Trading page to manage a grid bot.
</Note>

## Choose an eligible account

Create or import an account in [Account Management](https://app.owly.fi/accounts), then return to Grid Trading. The creation selector requires an account with a readable, positive available balance and no running bot. Accounts configured for a different bot type are excluded.

- **API Wallet** and **Hyperliquid Sub-account** accounts can be used when they meet those checks.
- **On-chain Lending / LeverAcc** accounts are excluded from the grid account selector.
- Legacy **Owly-managed sub-accounts** cannot update bot settings or start bots. Move their remaining funds to a self-custodial account through the supported withdrawal flow.

An account missing from the selector may still exist in Account Management. Check its type, balance, and existing bot configuration before adding another account.

## Configure the grid

Click **Create**, choose an account and contract pair, and review the following fields.

| Field | Meaning |
| --- | --- |
| Direction | Neutral, Long, or Short |
| Margin and leverage | Cross or Isolated, within the selected market's allowed leverage |
| Lower and upper prices | The grid's price range; the upper price must exceed the lower price |
| Grid count | Number of intervals; at least 2, subject to the estimated available order quota |
| Investment | Total capital allocated to the grid, entered to two decimal places; must be positive and less than the account's available balance |
| Price algorithm | Arithmetic uses equal price differences; Geometric uses equal price ratios |
| Trigger price | Optional; when enabled, start after price reaches the selected Above or Below condition |
| Initial position | Available in Long or Short mode; disabled in Neutral mode |
| Take profit / stop loss | Optional strategy price levels that initiate risk exit |
| Sync interval | Order reconciliation interval; the form starts at 15 seconds |

The page estimates minimum investment, quantity per order, and profit per grid from the chosen market and range. These are estimates; exchange order minimums, precision, fees, available margin, and live prices still determine whether the bot can start and execute.

<Warning>
Increasing the grid count divides investment across more orders. A larger grid count does not guarantee more profit and can leave individual orders below the exchange minimum. Leave available margin for losses and fees.
</Warning>

## Understand direction and initial positions

**Neutral** places buy orders below and sell orders above the reference price. It does not automatically open a directional base position.

**Long** adds long exposure with buys and uses reduce-only sells to reduce exposure. **Short** adds short exposure with sells and uses reduce-only buys to reduce exposure. Both directional modes can build an initial position when enabled. Review existing positions before starting; an incompatible position or insufficient margin can prevent activation.

## Save, start, and stop

1. **Save** stores the configuration without starting the bot.
2. Use the start action, review the confirmation, and confirm to start. If saving succeeds but starting fails, the configuration remains saved; check the error and status before retrying.
3. Monitor the running state, account balance, orders, and positions. A saved configuration or accepted request does not prove every grid order has filled.
4. Stop the bot before editing. Running grids are read-only in the editor.
5. In the stop dialog, review **Close all positions as well**, which is selected by default. Clearing it requests a stop without closing positions; retaining it requests stop and close. Check the resulting orders and positions after either action.

Take-profit and stop-loss triggers leave normal grid maintenance and initiate risk exit. Execution can be delayed, rejected, or partially filled. A stop, close request, or risk threshold does not guarantee an immediate fill or a fixed final loss.

## UI settings and API compatibility

The current form sends total investment as `total_invest`. It does not ask for a per-order `order_size` or a separate `bootstrap_size`; older configurations may still contain those fields. Do not treat an old per-order example as the current investment input.

New grid configurations use `account_mode: "auto"` unless an existing configuration already specifies a mode. The editor does not offer an account-mode selector, so this is separate from any Unified Account setup required when adding the account.

The payload retains compatibility with `trailing_up_limit` and `trailing_down_limit`, and can read historical trailing values. Both trailing controls are currently disabled in the UI; newly created form values leave them at `0`. A field being accepted or retained by the backend does not mean users can enable it in the editor. Likewise, backend parameters such as `rebalance_tolerance_bps` are not current editable form controls.
