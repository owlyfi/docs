# Owlyfi Referral System

Share your referral code or link to invite users to Owly. Eligible trading activity can generate direct (L1) and indirect (L2) rewards, while invited users may receive a temporary platform trading fee discount.

## Referral Tiers & Rewards

The referral system supports Normal, Advanced, and VIP tiers. The applicable configuration determines each tier's qualifying fee contribution, L1 and L2 reward ratios, referee discount, discount duration, and invite limit. These values can change; a fixed table in this guide would not describe every active configuration.

Automatic tier evaluation uses the cumulative eligible builder fees generated by active users you directly invited (L1). Some accounts may have an assigned tier or a separately adjusted invite allowance. Check your current tier, invite usage, available rewards, and reward records on the **Referral** page.

Rewards use the **actual builder fees recorded for eligible trades**, multiplied by the applicable referral reward ratio. A lower fee paid by an invited user can therefore reduce the fee base used for rewards. Trading volume alone does not establish a reward amount.

## How Referee Discounts Work

When a referral is bound, the system sets a discount expiry using the inviter's applicable tier rules. The discount duration is separate from the browser's referral attribution window.

- During the discount window, eligible Owly-managed strategies can apply a reduced builder fee automatically.
- The discount ratio follows the inviter's applicable tier configuration; it is not necessarily frozen at registration.
- Discounts reduce the trading fee charged. They do not create a separate cash rebate that the invited user must withdraw.
- A strategy with its own builder fee configuration may follow different rules. Check the applicable fee before trading.

See [Fee Structure](/faq/fees) for the difference between trading fees and the builder authorization ceiling.

## Referral Attribution

Owly uses **first-touch attribution within the same browser** before registration:

1. A valid referral link stores the first code in a browser cookie for up to **30 days**.
2. While that cookie remains valid, later referral links do not replace it. Referral capture does not replace an existing signed-in user's inviter.
3. Registration attempts to use the stored code. An invalid code can be rejected without preventing registration.

This cookie is not a permanent account binding: clearing cookies, expiry, or using another browser or device can remove the stored attribution. Once the account has an inviter, the normal binding flow does not allow replacing that inviter. If no inviter was applied at registration, an eligible user can enter a code once on the Referral page.

Referral codes contain **4–16 letters, numbers, underscores, or hyphens**. Binding is subject to code validity, available invite capacity, and referral eligibility checks.

## Earnings & Settlement

Rewards are calculated by a scheduled settlement process from recorded builder fees and then added to your available reward balance. The settlement schedule and upstream data availability affect when records appear; a trade does not immediately create a withdrawable reward.

An invitation can remain `pending` until eligible fee-generating activity has been recorded. The Referral page distinguishes invited users, users who have traded, reward records, and withdrawal history.

### Withdrawals

1. Open **Referral** and check your withdrawable reward balance.
2. Enter an amount within that balance. The current withdrawal form requires at least **1 USDC**; the applicable withdrawal rules may impose a higher minimum.
3. Submit the request. The requested amount is deducted from your available reward balance while it is processed.
4. Follow the request in withdrawal history and check its final status and transaction reference.

| Status | Meaning |
| :--- | :--- |
| `pending` | Submitted for review |
| `approved` | Approved for processing |
| `processing` | Processing is underway |
| `completed` | Recorded as completed |
| `rejected` / `failed` | Review rejected the request, or processing failed; check the record for details |

<Note>
Submission is not an immediate on-chain transfer. Use the withdrawal record to confirm the outcome; this guide does not guarantee a fixed processing time.
</Note>

## Calculation Example

For illustration only, suppose an eligible user's **actual builder fees** total $5 and the applicable L1 reward ratio is 30%. Your reward is `$5 × 30% = $1.50`. If another eligible user generates $2 in actual fees and the applicable L2 ratio is 5%, the L2 reward is `$2 × 5% = $0.10`.

These example ratios are not a statement of the current tier policy. Use the applicable rules and your settled reward records for actual amounts.

## Eligibility

Self-referrals and circular referral chains are rejected. Referral codes also have usage limits unless the applicable tier or account allowance permits otherwise. Do not use fabricated accounts or artificial activity to evade the referral rules.
