## Step 1: Preparation

### 1.1 Register Owly Account

<Steps>
  <Step title="Visit Owly">
    Go to [app.owly.fi](https://app.owly.fi)
  </Step>
  <Step title="Connect Wallet">
    Click "Connect Wallet" to connect your main wallet
  </Step>
  <Step title="Sign Verification">
    Sign the verification message to confirm wallet ownership
  </Step>
  <Step title="Registration Complete">
    Complete registration and enter the Owly platform
  </Step>
</Steps>

### 1.2 Confirm Fund Manager Registration

<Check>Fund manager must be a registered Owly user</Check>
<Check>Obtain the fund manager's wallet address</Check>

<Warning>
If the fund manager is not registered, the assignment will fail.
</Warning>

## Step 2: Create Sub Account and API on Hyperliquid

### 2.1 Prerequisites

<Note>
Creating a native sub-account requires meeting [Hyperliquid's current eligibility rules](https://hyperliquid.gitbook.io/hyperliquid-docs/trading/sub-accounts). Existing sub-accounts can be imported below.
</Note>

### 2.2 Create Sub Account

<Steps>
  <Step title="Visit Hyperliquid">
    Go to [app.hyperliquid.xyz](https://app.hyperliquid.xyz)
  </Step>
  <Step title="Connect Wallet">
    Connect your main wallet
  </Step>
  <Step title="Navigate to Sub Accounts">
    Find Sub Accounts in the menu
  </Step>
  <Step title="Create Sub Account">
    Click Create Sub Account, enter a name and confirm creation
  </Step>
</Steps>

### 2.3 Create API Key for Sub Account

<Steps>
  <Step title="Enter Sub Account">
    Select the Sub Account you just created
  </Step>
  <Step title="Create API Key">
    Click API, create a new API Key
  </Step>
  <Step title="Save Private Key">
    **Important**: Securely save the private key - it's only shown once
  </Step>
</Steps>

<Warning>
**Each Sub Account must have its own API Key!**

An API Wallet signing for several accounts shares its nonce state, which can cause conflicts. Owly requires separate API Wallets; this does not restrict a key to one sub-account at the protocol level. See [Choose an Account Type](/guide/account-types).

Owly requires: **One Sub Account = One dedicated API Key**.
</Warning>

### 2.4 Complete authorizations during import

You do not need the old authorization test page. The Owly import form checks existing authorizations and guides any additional signatures; completed authorizations do not need repeating. Use the sub-account's master wallet and review the address, site, and requested authorization. See [Choose an Account Type](/guide/account-types).

## Step 3: Import Sub Account to Owly

### 3.1 Access Add Page

<Steps>
  <Step title="Login to Owly">
    Sign in to Owly with the Hyperliquid master wallet that owns this sub-account
  </Step>
  <Step title="Go to Sub Account Management">
    Navigate to **Sub Account Management**
  </Step>
  <Step title="Add Sub Account">
    Click **Create Sub-Account**, choose the appropriate guidance option, then select **Hyperliquid Sub-account**
  </Step>
</Steps>

### 3.2 Select Sub Account

Owly will automatically fetch your Sub Account list. Select the Sub Account you want to import.

### 3.3 Enter API Key

<Steps>
  <Step title="Enter Private Key">
    Enter the authorized API Wallet private key only in the dedicated **API Wallet Private Key** form, never in the Assistant. Native sub-accounts have no private key of their own; do not enter your master wallet private key or seed phrase
  </Step>
  <Step title="Set Display Name">
    Set a display name for this account
  </Step>
</Steps>

### 3.4 Confirm Import

Owly checks API Wallet validity and existing authorizations. Complete any required authorization shown by the form, verify the account, and finish import. Creation may finish directly when the required authorizations already exist.

## Step 4: Assign to Fund Manager

<Steps>
  <Step title="Go to Sub Account Management">
    Navigate to **Sub Account Management** in Owly
  </Step>
  <Step title="Select Sub Account">
    Choose the Sub Account to assign
  </Step>
  <Step title="Assign Fund Manager">
    Click **Assign Fund Manager**
  </Step>
  <Step title="Enter Address">
    Enter the fund manager's wallet address
  </Step>
  <Step title="Confirm Assignment">
    Confirm the assignment
  </Step>
</Steps>

<Note>
If the fund manager hasn't registered on Owly, assignment will fail with "Address not registered" message.
</Note>

## Step 5: Daily Management

### View Account Status

Go to **Sub Account Management** to view all accounts, including positions, P&L, and Bot running status.

### Stop Bot

<Steps>
  <Step title="Select Account">
    Select the Sub Account
  </Step>
  <Step title="Stop Bot">
    Click **Stop Bot**
  </Step>
  <Step title="Complete">
    Bot will stop executing new trades
  </Step>
</Steps>

### Remove Fund Manager Assignment

<Steps>
  <Step title="Select Account">
    Select the Sub Account
  </Step>
  <Step title="Remove Assignment">
    Click **Remove Assignment**
  </Step>
  <Step title="Confirm">
    After confirmation, fund manager loses management permissions and associated Bots will automatically stop
  </Step>
</Steps>

### Emergency Revocation (On-chain)

To completely revoke an API Key:

<Steps>
  <Step title="Visit Hyperliquid">
    Go to Hyperliquid
  </Step>
  <Step title="Enter Sub Account">
    Navigate to the corresponding Sub Account
  </Step>
  <Step title="Revoke API">
    Delete/revoke the API Key
  </Step>
</Steps>

## Permissions & Security

### API Key Technical Limitations

| Limitation | Description |
|:-----------|:------------|
| **Scope** | API Key can sign operations for main account and all Sub Accounts |
| **Nonce Mechanism** | Each API Key uses an independent Nonce sequence |
| **Shared Signing Risk** | Accounts using one API Wallet share nonce state, which can cause conflicts |
| **Owly Requirement** | Each Sub Account must use a dedicated API Key |

### API Wallets and funding actions

API Wallets sign authorized trading actions. Asset owners should review and complete transfers or withdrawals themselves through supported Hyperliquid flows. A leaked API Wallet can enable malicious trading and losses; lack of withdrawal permission does not make funds risk-free. See [Choose an Account Type](/guide/account-types) for account roles and secret-input boundaries.

### Fund Manager Permissions

After assignment, fund managers can:

| Operation | Permission |
|:----------|:-----------|
| Configure and start/stop Copy Trade Bot | ✅ Allowed |
| View positions and P&L | ✅ Allowed |
| Withdraw or transfer funds | ❌ Not Allowed |
| Modify account settings | ❌ Not Allowed |
| Assign to others | ❌ Not Allowed |

### Security Recommendations

<Warning>
1. **Keep API private keys secure**: enter them only in Owly's dedicated import or update form, never in the Assistant, support, or chat. Never enter master wallet private keys or seed phrases in those forms
2. **Use dedicated API Key for each Sub Account**
3. **Only assign to trusted fund managers**
4. **Regularly check trading records** - stop Bot immediately if anomalies detected
5. **If API leak suspected** - immediately revoke on Hyperliquid
</Warning>

### Risk Disclosure

| Scenario | Risk | Your Control |
|:---------|:-----|:-------------|
| Fund manager strategy loss | Capital reduction | Stop Bot, remove assignment |
| High leverage operation | Liquidation risk | Monitor positions, intervene promptly |
| API Key leak | Malicious trading | Revoke API on Hyperliquid |
| Extreme market conditions | Significant losses | Set stop-loss in advance |

## FAQ

<AccordionGroup>
  <Accordion title="Cannot create Sub Account">
    Check [Hyperliquid's current eligibility rules](https://hyperliquid.gitbook.io/hyperliquid-docs/trading/sub-accounts). The ordinary API Wallet route does not require first creating a native sub-account
  </Accordion>
  <Accordion title="Import fails with 'Builder Fee not set'">
    Return to the import form and complete any required authorization with the sub-account's master wallet. Do not use the old authorization test page
  </Accordion>
  <Accordion title="Cannot find my Sub Account">
    Confirm you're using the main wallet that created the Sub Account
  </Accordion>
  <Accordion title="Assignment fails with 'Address not registered'">
    Fund manager needs to register an Owly account first
  </Accordion>
  <Accordion title="Can fund manager withdraw my funds?">
    No, API Key has no withdrawal permissions
  </Accordion>
  <Accordion title="Why does each Sub Account need a separate API?">
    A shared API Wallet shares nonce state and may cause conflicts. Owly requires a dedicated API Wallet for each imported sub-account
  </Accordion>
</AccordionGroup>
