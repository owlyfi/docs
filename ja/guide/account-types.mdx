## Hyperliquid の API ウォレット

Hyperliquid の **API ウォレット**は、マスターアカウントが承認する取引署名用のウォレットです。**エージェントウォレット**とも呼ばれます。マスターアカウントやそのネイティブサブアカウントで、対応する取引操作に署名できます。**API ウォレットを生成または承認しても、新しい Hyperliquid マスターアカウントは作成されず、取引資金も別途割り当てられません。** 残高、ポジション、損益を照会する際は、資金が属するマスターアカウントまたはサブアカウントのアドレスを使います。[Hyperliquid の API ウォレットのドキュメント](https://hyperliquid.gitbook.io/hyperliquid-docs/for-developers/api/nonces-and-api-wallets#api-wallets)を参照してください。

API ウォレットの承認には、資金ウォレットからの入金や、マスターアカウントから外部ウォレットへの出金に署名する権限は含まれません。入金は資金を保有するウォレットから開始し、出金にはマスターウォレットの署名が必要です。API ウォレットを入金先に指定することはできません。これらの制約は外部との入出金に関するもので、内部の資金操作にはエージェントが実行できるものもあります。[Hyperliquid の入金ガイド](https://hyperliquid.gitbook.io/hyperliquid-docs/onboarding/how-to-start-trading)と[出金エンドポイント](https://hyperliquid.gitbook.io/hyperliquid-docs/for-developers/api/exchange-endpoint#initiate-a-withdrawal-request)を参照してください。

<Warning>
API ウォレットが漏えいすると、不正取引や損失につながるおそれがあります。API ウォレットのアドレスに資金を送ったり、コピートレード用の資金を保管する別アカウントとして扱ったりしないでください。
</Warning>

## Owly のログイン用アカウントと取引アカウント

Owly では、管理対象の取引アカウントを総称して「サブアカウント」と呼びます。作成画面に表示される種類は **API ウォレット**、**Hyperliquid サブアカウント**、**オンチェーンレンディング（Alpha）**の 3 つです。Hyperliquid サブアカウントでは、既存のネイティブサブアカウントを取り込むか、マスターアカウントが条件を満たす場合に新規作成します。オンチェーンレンディングでは、画面内の LeverAcc インターフェースからプロトコルのアカウントを作成または接続します。

- **Owly メインアカウント**は、Owly へのログインとアカウント管理に使うウォレットです。
- **取引アカウント**には、Hyperliquid の取引資金とポジションが属します。
- **API ウォレット**は、取引アカウントから承認を受けて取引に署名します。取引資金は取引アカウントに残ります。

**Owly メインアカウントと取引アカウントには、同じウォレットアドレスを使用できます。** ログイン用と取引用で別のアドレスを使うこともできます。その場合は、ログイン、入金、署名に使うアドレスをそれぞれ確認してください。同じアドレスを使う場合、新たにウォレットアカウントを作る必要はありません。

**1 つの Owly メインアカウントで管理できる有効な取引アカウントは、3 種類を合わせて最大 10 件です。** たとえば API ウォレットと Hyperliquid サブアカウントが合計 9 件あり、有効なオンチェーンレンディングアカウントが 1 件ある場合は上限に達しています。後述する Hyperliquid ネイティブサブアカウントの作成条件や上限は別に適用されます。

## 3 種類のアカウントを比較する

| 種類 | こんなときに使う | 用意するもの | 注意点 |
|:--|:--|:--|:--|
| **API ウォレット** | 自分で管理する Hyperliquid メインアカウントで取引する場合。初めての利用者の多くに適しています | 承認の署名に使う取引ウォレットを Owly に接続します | 取引アカウントごとに別の Hyperliquid マスターアドレスを使います。そのうち 1 つは Owly のログインアドレスと同じでも構いません |
| **Hyperliquid サブアカウント** | Hyperliquid マスターアカウント配下のネイティブサブアカウントを管理する場合 | マスターウォレットと既存のサブアカウント、または新規作成の資格が必要です。専用 API ウォレットは Owly が生成します | 新規作成時は Hyperliquid の作成条件と空き枠が確認されます |
| **オンチェーンレンディング（Alpha）** | 担保を差し入れ、LeverAcc で借りた USDC を使って取引する場合 | 設定画面で指定される USDC とガス代用の資産を持つ資金ウォレット、または既存の LeverAcc 取引アカウントが必要です | Alpha 版です。アカウント作成、紐づけ、借入、戦略開始は別々の操作です |

## API ウォレットの上限と不要な承認の取り消し

Hyperliquid のマスターアカウントでは、デフォルトで **名前付き API ウォレットを最大 3 個**承認できます。この枠は、そのマスターアカウントを使うアプリ全体で共有されます。名前なし API ウォレット 1 個も利用でき、ネイティブサブアカウント 1 件につき名前付きの枠が 2 個増えます。[Hyperliquid 公式の API ウォレット上限](https://hyperliquid.gitbook.io/hyperliquid-docs/for-developers/api/exchange-endpoint#approve-an-api-wallet)を参照してください。この承認枠は、前述の Owly の取引アカウント上限とは別です。

上限に達して API ウォレットを作成または更新できない場合は、次の手順で空き枠を確保します。

1. [Hyperliquid の API ページ](https://app.hyperliquid.xyz/API)を開き、承認元のマスターウォレットを接続します。Hyperliquid サブアカウントの場合は、そのマスターウォレットを使用します。
2. API ウォレットの名前とアドレスを確認し、不要になったものを削除するか承認を取り消します。Owly や別のアプリが引き続き使用している API ウォレットの承認を取り消すと、そのアプリはそのウォレットで取引できなくなります。
3. 空き枠を確認してから Owly に戻り、API ウォレットの作成または承認の更新をやり直します。

## API ウォレットの有効期間と更新

Hyperliquid の API ウォレット承認の有効期間は **最大 180 日**です。この期限が適用されるのは承認です。取引アカウント自体は存続します。[Hyperliquid 公式の API ウォレット承認ルール](https://hyperliquid.gitbook.io/hyperliquid-docs/for-developers/api/exchange-endpoint#approve-an-api-wallet)を参照してください。

Owly のデフォルトの有効期間は次のとおりです。

| アカウントの種類 | API ウォレットのデフォルトの有効期間 |
|:--|:--|
| API ウォレット | **180 日** |
| Hyperliquid サブアカウント | **180 日** |
| LeverAcc を使うオンチェーンレンディング（Alpha） | 現在、設定画面では **90 日**と表示されます。検証済みの実際の有効期限を確認してください |

<Warning>
**API ウォレットと Hyperliquid サブアカウント**では、定期的な有効期限チェックにより、承認期限まで残り **10 分**以内になると稼働中のボットの停止が試行されます。このチェックの対象に LeverAcc は含まれません。停止の正確な時刻や、ポジションの処理完了は保証されません。期限まで十分な余裕を持って承認を更新し、新しい期限が確認されたことを確かめてから、ボットの稼働状況とポジションを確認してください。
</Warning>

## Owly の API ウォレットタイプ

このタイプでは、資金を保有する EVM アドレスを **独立した Hyperliquid マスターアカウント**として使います。Hyperliquid のネイティブサブアカウントとは異なります。このタイプの取引アカウントを複数追加する場合は、同じマスターに複数の API ウォレットを作る方法では対応できません。マスターアドレスをアカウントごとに用意してください。そのうち 1 つには Owly のログインアドレスを使えます。

API ウォレット（**API 財布**）を選択し、アカウント名を入力して、取引アカウントのウォレットを **Connect** で接続します。表示されたアドレスを確認してください。Owly のログインアドレスと同じでも構いません。Hyperliquid で未有効化の場合は、画面の案内に従って入金し、有効化を待ってから続けます。エージェント、Vault、ネイティブサブアカウントのアドレスは、このタイプの資金を保有するウォレットとして使えません。設定画面に API ウォレットの秘密鍵を入力する項目はありません。

Owly は取引アカウントで **統一アカウント（Unified Account）** モードが有効か確認し、必要な場合は有効化の署名を求めます。その後、API ウォレットを生成して安全に保管し、公開アドレスを表示します。接続中の取引ウォレットで承認してください。必要に応じて、上限を確認したうえで **Builder 手数料を承認**します。確認済みの承認はスキップされます。

<Info>
Owly は生成した API 取引キーを管理します。マスターウォレットは自分で管理してください。残高、ポジション、損益は取引アカウントのアドレスに紐づきます。API ウォレットには入金しないでください。設定時に Hyperliquid の API ページでウォレットを手動作成したり、秘密鍵をコピーしたりする必要はありません。
</Info>

初めてアカウントを作る場合は、[クイックスタート](/ja/guide/quick-start)に従って、準備、入金、接続、承認を行ってください。

## Hyperliquid サブアカウント

Hyperliquid のマスターアカウント配下にある **ネイティブサブアカウント**です。前述の独立したマスターアカウントとは異なります。[Hyperliquid のルール](https://hyperliquid.gitbook.io/hyperliquid-docs/trading/sub-accounts)では、取引高が **$100,000** に達すると、最大 **10 件**まで作成できます。その後は取引高が **$100,000,000** 増えるごとに 1 件追加でき、最大 **50 件**になります。10 件は初期の上限です。この枠は、前述の Owly のアカウント上限とは別です。

サブアカウントのマスターウォレットで Owly にログインし、**Hyperliquid サブアカウント**を選んで一覧を表示します。既存のサブアカウントを選択し、アカウント名を入力します。Owly はマスターアカウントの統一アカウントモードを確認し、必要なら有効化の署名を求めたうえで、取り込み用の専用 API ウォレットを生成して保存します。生成されたアドレスを確認し、**マスターウォレット**で API ウォレットと、必要な場合は Builder 手数料を承認してください。Hyperliquid で API ウォレットを作成したり、秘密鍵を入力したりする必要はありません。追加済みのサブアカウントを重複して選ぶことはできません。

マスターアカウントが作成条件を満たし、空き枠があると Owly が確認できれば、選択画面から新しいネイティブサブアカウントも作成できます。有効で未使用のアカウント名を入力し、作成を選択します。案内が表示された場合は、先にマスターアカウントの API ウォレットを承認してください。Owly がネイティブサブアカウントの作成を送信するために必要です。Hyperliquid が新しいアカウントを確認した後、取り込みを続け、専用の API ウォレットを承認してください。作成できない場合は、マスターウォレットと [Hyperliquid のサブアカウント画面](https://app.hyperliquid.xyz/subAccounts)に表示される作成資格を確認してください。

<Warning>
ネイティブの Hyperliquid サブアカウントには固有の秘密鍵がありません。API ウォレットを承認するのはマスターアカウントです。Owly はノンスの共有による競合を減らすため、取り込んだサブアカウントごとに別々の API ウォレットを自動生成します。これによって、プロトコル上でその API ウォレットの対象が 1 つのサブアカウントに限定されるわけではありません。[サブアカウントの署名](https://hyperliquid.gitbook.io/hyperliquid-docs/for-developers/api/exchange-endpoint#subaccounts-and-vaults)と[API ウォレット](https://hyperliquid.gitbook.io/hyperliquid-docs/for-developers/api/nonces-and-api-wallets#api-wallets)を参照してください。
</Warning>

アカウント管理を委任する方法は、[資産所有者向けガイド](/ja/guide/owner-guide)を参照してください。

## オンチェーンレンディング（Alpha）

**オンチェーンレンディング**では、LeverAcc アカウントを接続し、担保を差し入れて借りた USDC で取引します。アカウントの種類を選ぶ画面で、**オンチェーンレンディング（Alpha）**を選択します。

<Warning>
このアカウントタイプは **Alpha** 版です。プロジェクトの紐づけが確認され、有効な実行承認があるアカウントをコピートレードに選べます。現在のグリッドボットでは LeverAcc アカウントを選択できません。アカウントを追加しても、戦略の開始や資金の借入は自動で行われません。利用可否は、アプリの現在の設定とプロトコルの確認結果によります。
</Warning>

1. アカウント名を入力し、資金ウォレットを接続します。このウォレットは Owly のログイン用ウォレットと異なっていても構いません。Owly は既存の LeverAcc 取引アカウントを検出します。秘密鍵を貼り付けたり、取引コントラクトのアドレスを手入力したりする必要はありません。
2. 取引アカウントが必要な場合は、Owly 内の LeverAcc 作成画面に従います。設定時は、まず資金ウォレットの Arbitrum 上の USDC とガス代用の残高を確認します。表示される最低額を満たし、アカウントの作成と有効化が確認されるまで待ってください。
3. 利用可能な場合は、準備のため USDC から ETH や HYPE に交換できます。それぞれの予算は別です。見積もりの支出額とトークンの利用許可額を個別に確認してください。ETH を準備しただけでは HYPE の要件は満たせません。見積もりが得られない場合は、指定された資産を自分で用意して残高を再確認してください。
4. 資金ウォレットと取引アカウントのアドレスを確認し、プロジェクトの紐づけに進みます。プロジェクトが一致しない場合は **Link to Owly** を選び、署名の要求とコントラクト取引を確認します。プロジェクトを変更するには、未返済の借入や変更を妨げるプロトコル上のリスクがないことが条件です。変更すると以前の実行用ウォレットは無効になります。
5. 資金ウォレットで、実行用ウォレットと必要な Builder 手数料を承認します。Owly が紐づけを確認し、アカウントの追加完了を表示するまで待ってください。すでに処理中の操作がある場合は、新しい操作を始める前に再開するか、状況を確認してください。
6. **アカウント**画面で、LeverAcc アカウントの入金、返済、出金を選ぶか、メニューから借入または資金移動を選びます。いずれも画面内の LeverAcc インターフェースを開きます。入金と承認が済んだら、該当する戦略設定でアカウントを選択し、戦略の開始を別途確定します。

戦略を停止している間も、借入に利息が発生する場合があります。ボットの停止やポジションの決済だけでは借入は返済されません。返済と出金の制限は LeverAcc の画面で確認してください。Alpha 版の利用可否や対応する取引機能は、その時点の画面表示に従います。

## 旧 Owly 管理アカウント

旧 Owly 管理アカウントタイプ（`sub`）では、新規作成、入金、内部振替、ボットの開始や再開、設定更新の提供を終了しました。既存のアカウントでは引き続き、閲覧、ボットの停止や終了、対応する出金を行えます。この制限の対象外である **Hyperliquid サブアカウント**（`hl_sub`）は、前述の手順で利用できます。

## 機密情報の取り扱い

- シードフレーズ、Owly ログイン用ウォレットの秘密鍵、取引用マスターウォレットの秘密鍵を、アシスタント、サポート、第三者に送らないでください。
- 新しい API ウォレットや Hyperliquid サブアカウントの設定では、Owly が API 取引キーを生成して保存します。秘密鍵を手動で作成、コピー、インポートする必要はありません。
- アシスタントはアカウントの種類と公開アドレスを使って手順を説明できます。接続、承認、入金、資金移動、取引の内容は自分で確認してください。
- API ウォレットが漏えいすると、不正取引や損失につながるおそれがあります。漏えいした場合は該当するボットを停止し、Hyperliquid で承認を取り消してください。有効期限の更新や交換は、Owly のアカウント管理画面の案内に従ってください。
