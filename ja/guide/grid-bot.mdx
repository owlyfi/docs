[グリッド取引](https://app.owly.fi/trading-bots/grid)で**取引ボット→グリッド取引**を開きます。ボットを管理する前にサインインしてください。

## 現在のサポート

グリッドエディターは、永久市場、**ニュートラル**、**ロング**、および**ショート** 方向、**算術** またはをサポートします。 **幾何学的**の間隔、および**クロス**または**分離**のマージン。また、トリガー価格、方向性のある初期ポジション、戦略のテイクプロフィットとストップロスの価格も公開します。

<Note>
このエディタではスポットグリッドは利用できません。上向きおよび下向きのトレーリング コントロールは表示されますが、無効になっています。別の[取引ターミナル](/ja/guide/trading-terminal)のグリッドオプションもプレビューです。グリッド取引ページを使用してグリッド ボットを管理します。
</Note>

## 対象となるアカウントを選択してください

[アカウント管理](https://app.owly.fi/accounts) でアカウントを作成またはインポートし、グリッド取引に戻ります。作成セレクターには、読み取り可能でプラスの利用可能残高があり、ボットが実行されていないアカウントが必要です。異なるボットタイプ用に構成されたアカウントは除外されます。

- **API ウォレット** および **Hyperliquid サブアカウント** アカウントは、これらの小切手を満たす場合に使用できます。
- **オンチェーンレンディング / LeverAcc** アカウントはグリッドアカウントセレクターから除外されます。
- 従来の **Owly が管理するサブアカウント** では、ボット設定を更新したり、ボットを開始したりできません。サポートされている出金フローを通じて、残りの資金を自己保管口座に移動します。

セレクターに表示されないアカウントがアカウント管理にまだ存在している可能性があります。別のアカウントを追加する前に、そのタイプ、残高、既存のボット構成を確認してください。

## グリッドを構成する

**作成** をクリックし、アカウントと契約のペアを選択し、次のフィールドを確認します。

| フィールド | 意味 |
| --- | --- |
| 方向 | ニュートラル、ロング、ショート |
| 証拠金とレバレッジ | 選択した市場の許容レバレッジ内でクロスまたは孤立 |
| 下限価格と上限価格 | グリッドの価格帯。上限価格は下限価格を超える必要があります |
| グリッド数 | 間隔の数。少なくとも 2, (推定利用可能な注文割り当ての対象) |
| 投資 | グリッドに割り当てられた総資本。小数点第 2 位まで入力されます。プラスであり、アカウントの利用可能な残高よりも小さい必要があります |
| 価格アルゴリズム | 算術演算では等しい価格差を使用します。幾何学的には等価格比率を使用します |
| トリガー価格 | オプション;有効にすると、価格が選択した「上」または「下」の条件に達した後に開始されます。 |
| 初期位置 | ロングモードまたはショートモードで利用可能。ニュートラルモードでは無効になります |
| テイクプロフィット/ストップロス | リスク出口を開始するオプションの戦略価格レベル |
| 同期間隔 | 注文調整間隔;フォームは 15 秒から始まります |

このページでは、選択した市場と範囲からの最小投資、注文ごとの数量、グリッドごとの利益を推定します。これらは推定値です。為替注文の最小値、精度、手数料、利用可能なマージン、ライブ価格によっても、ボットが開始して実行できるかどうかが決まります。

<Warning>
グリッド数を増やすと、より多くの注文に投資が分割されます。グリッド数が大きくても、より多くの利益が保証されるわけではなく、個々の注文が取引所の最小値を下回る可能性があります。損失と手数料に備えて利用可能なマージンを残しておきます。
</Warning>

## 方向と初期位置を理解する

**ニュートラル** は、基準価格より下で買い注文を出し、基準価格より上で売り注文を出します。方向性ベースポジションは自動的にオープンしません。

**ロング** は買いでロングエクスポージャーを追加し、リデュースのみの売りを使用してエクスポージャーを減らします。 **ショート** は、売りによるショートエクスポージャーを追加し、エクスポージャーを減らすために削減のみの買いを使用します。どちらの方向モードも、有効にすると初期位置を構築できます。開始する前に既存のポジションを確認します。互換性のない位置やマージンが不十分な場合は、アクティベートできない可能性があります。

## 保存、開始、停止

1. **Save** は、ボットを起動せずに構成を保存します。
2. 開始アクションを使用し、確認を確認して開始を確認します。保存は成功したが開始に失敗した場合、設定は保存されたままになります。再試行する前にエラーとステータスを確認してください。
3. 実行状態、口座残高、注文、ポジションを監視します。保存された構成または受け入れられたリクエストは、すべてのグリッド注文が満たされたことを証明するものではありません。
4. 編集する前にボットを停止してください。実行中のグリッドはエディターでは読み取り専用です。
5. ストップダイアログで、デフォルトで選択されている**すべてのポジションもクローズ** を確認します。これをクリアすると、ポジションをクローズせずにストップが要求されます。それを保持すると、停止とクローズが要求されます。いずれかのアクションの後に結果として得られる注文とポジションを確認します。

テイクプロフィットとストップロスのトリガーは通常のグリッドメンテナンスを離れ、リスクエグジットを開始します。実行は遅延、拒否、または部分的に実行される可能性があります。ストップ、クローズリクエスト、またはリスクしきい値は、即時の約定や固定の最終損失を保証するものではありません。

## UI設定とAPI の互換性

現在のフォームでは、投資総額が `total_invest` として送信されます。注文ごとの `order_size` や個別の `bootstrap_size` は必要ありません。古い構成にはこれらのフィールドがまだ含まれている可能性があります。注文ごとの古い例を現在の投資入力として扱わないでください。

既存の構成ですでにモードが指定されていない限り、新しいグリッド構成は `account_mode: "auto"` を使用します。エディターにはアカウント モード セレクターが用意されていないため、これはアカウントの追加時に必要な統合アカウントのセットアップとは別のものです。

ペイロードは、`trailing_up_limit` および `trailing_down_limit` との互換性を維持しており、過去の末尾の値を読み取ることができます。現在、後続のコントロールは両方とも UI で無効になっています。新しく作成されたフォーム値は `0` のままになります。バックエンドによってフィールドが受け入れられたり保持されたりしても、ユーザーがエディターでそのフィールドを有効にできるわけではありません。同様に、`rebalance_tolerance_bps` などのバックエンド パラメータは、現在編集可能なフォーム コントロールではありません。

アカウントの設定については[アカウントタイプ](/ja/guide/account-types)、取引コストについては[手数料](/ja/faq/fees)を参照してください。
