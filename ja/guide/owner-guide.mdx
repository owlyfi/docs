Owly により、資産所有者は選択した取引権限を持つマネージャーを追加できます。 **マネージャーの承認は、後で追加されたアカウントを含む、所有者の下にあるすべてのアクティブな取引アカウントに適用されます。** これは、所有者とマネージャーの関係であり、1 つのサブアカウントに対する個別の割り当てではありません。

## アカウントを準備する

アセット所有者として [Owly](https://app.owly.fi/accounts) にサインインします。通常の取引口座の場合は、[API ウォレット設定](/ja/guide/quick-start) を使用します。以下で説明するように、ネイティブ Hyperliquid サブアカウントを追加することもできます。 Owly の共有アカウント制限と Hyperliquid のネイティブ資格ルールは別個です。 [アカウントタイプ](/ja/guide/account-types)を参照してください。

### ネイティブ Hyperliquid サブアカウントを追加

1. ネイティブサブアカウントを所有する、または作成するHyperliquid マスターウォレットでサインインします。
2. アカウント管理を開き、**サブアカウントの作成** を選択し、次に**Hyperliquid サブアカウント** を選択します。
3. 既存のサブアカウントを選択します。資格がある場合は、同じフォームで **サブアカウントの作成** を選択し、最大 16 文字の一意の名前を入力し、承認と作成のプロンプトに従うことができます。 Owly はまず、このフローで必要な通常の API ウォレット認証を準備または再利用します。続行する前に、ウォレットのアドレスと結果を確認してください。
4. 作成が確認されていない場合は、再度作成する前にサブアカウントのリストを更新して元の試行を確認してください。
5. アカウントの表示名を入力して続行します。必要な統合アカウントの有効化、専用の API ウォレットの承認、およびマスター ウォレットでのビルダー料金の承認を確認して署名します。
6. 完了を待ち、選択した取引口座アドレスを確認します。秘密キーを入力したりコピーしたりしません。

[Hyperliquid](https://app.hyperliquid.xyz/subAccounts) で対象となるネイティブ サブアカウントを作成し、Owly で選択することもできます。既存のネイティブ サブアカウントは引き続きサポートされます。従来の Owly で管理されるウォレットは別のアカウント タイプです。これらのウォレットでは、新規作成、新しいボットのセットアップ、ボットの再起動が無効になっています。

<Note>
ネイティブ サブアカウントには独自の秘密キーがありません。マスター ウォレットは API ウォレットを承認します。 Owly は、インポートごとに専用の API ウォレットを生成し、共有ノンスの競合を軽減します。これは、エージェントを Hyperliquid プロトコル レベルでその 1 つのサブアカウントに制限するものではありません。
</Note>

## マネージャーを追加

マネージャーは、EVM アドレスを持つ登録済みの Owly ユーザーである必要があります。自分自身を追加したり、同じマネージャーを 2 回追加したりすることはできません。各所有者は、**から 20 までのマネージャー** を追加できます。

1. アカウント管理で、**マネージャーアカウント** を見つけ、**マネージャーの追加** を選択します。
2. 管理者の登録ウォレットアドレスと任意のニックネームを入力します。
3. **表示**、**ボットの開始**、**ボットの停止**の権限を確認します。デフォルトでは 3 つすべてが選択されています。付与する予定の権限のみを保持してください。
4. 確認します。管理者は、**管理対象サブアカウント**を使用して、これらの権限に従ってあなたのアカウントにアクセスできます。

<Warning>
これにより、将来の追加を含む、アクティブなアカウント全体へのアクセスが許可されます。確認する前に、所有者レベルのスコープ全体を確認してください。専用の取引サブアカウントでは、マネージャーの承認がそのサブアカウントに固有のものにはなりません。
</Warning>

## 権限

| 許可 | できること |
| --- | --- |
| **ビュー (`VIEW`)** | サポートされている管理ビューを通じてアカウントと戦略情報を表示します |
| **ボット開始 (`START`)** | サポートされているボットを開始または再起動します |
| **ボットを停止 (`STOP`)** | ボットを停止するか、終了とクリーンアップをリクエストします |

ボット構成の変更には、開始/停止権限チェックが使用されます。個別のマネージャー構成許可スイッチはありません。マネージャー権限では、出金、アカウント所有権/設定の編集、他のマネージャーの追加などの所有者操作は許可されません。アカウントの種類の制限とウォレットの承認は引き続き適用されます。

API ウォレットは、承認された取引アクションに署名します。アセットオーナーは、外部からの資金調達や引き出しのためにファンディングウォレットまたはマスターウォレットの署名役割を保持します。漏洩したAPI ウォレットは依然として悪意のある取引を通じて損失を引き起こす可能性があります。 LeverAcc アカウントの場合、LeverAcc を通じて担保、借金、返済、プロトコルの引き出しを管理します。ボットを停止してもローンは返済されません。

## 取引の監視と停止

アカウント管理とポートフォリオでアカウント残高、ポジション、注文、損益、ボットのステータスを確認します。実行時とクリーンアップのステータス、および表示されたライフサイクルの状態を確認します。

- **Stop** は自動実行を停止します。それ自体は既存のポジションを決済しません。
- **クローズ/終了** は、戦略の終了とポジション/注文のクリーンアップを要求します。クリーンアップ結果と実際の位置を確認します。すべてのクローズ試行が成功するとは限りません。
- クリーンアップが保留中または失敗した場合は、フォローアップが必要です。結果を確認するまで、アカウントに残りの証拠金義務の資金を供給したままにしておきます。

## マネージャーの変更または削除

マネージャー カードで **編集** を使用して、ニックネームまたは権限を更新します。 **削除** を使用して、マネージャーに対する所有者の承認を取り消します。

**マネージャーを削除しても、実行中のボットの停止、ポジションのクローズ、注文のキャンセル、Hyperliquid API ウォレットの承認の取り消しは自動的には行われません。** 取引を終了したい場合は、影響を受ける各ボットを自分で停止または閉じて、その状態と残りのエクスポージャを確認してください。 1 人のマネージャーを削除しても、別のマネージャーのアクセス権は取り消されません。

API ウォレットが侵害された可能性がある場合は、影響を受ける自動化を停止し、マスターウォレットを使用して [Hyperliquid API ページ](https://app.hyperliquid.xyz/API) でその承認を確認します。 Owly のアカウント管理フローに従って、交換を承認します。シード フレーズや秘密キーをアシスタント、サポート、またはマネージャーに決して送信しないでください。

## よくある質問

<AccordionGroup>
  <Accordion title="マネージャーを 1 つの取引口座だけに割り当てることはできますか?">
    現在のマネージャー関係は、所有者のアクティブなアカウントを対象としています。その所有者の下に別のネイティブ サブアカウントを作成しても、付与が 1 つのアカウントに限定されるわけではありません。
  </Accordion>
  <Accordion title="マネージャーの追加が失敗したのはなぜですか?">
    EVM アドレスを確認し、マネージャーが登録されていることを確認し、それが自分のアドレスまたは既存のマネージャーではないことを確認してください。所有者制限は 20 管理者です。
  </Accordion>
  <Accordion title="ネイティブのサブアカウントの作成が利用できないのはなぜですか?">
    フォームの資格と定員の結果に従ってください。既存の対象となるサブアカウントを選択することもできます。作成が確認されていない場合は、重複を避けるために再試行する前に更新してください。
  </Accordion>
  <Accordion title="マネージャーは資金を引き出すことができますか?">
    Owly の表示 / 開始 / 停止権限は、撤回または譲渡の権限を付与しません。所有者のウォレットとアカウントのプロトコル ルールがこれらのアクションを制御します。
  </Accordion>
</AccordionGroup>
