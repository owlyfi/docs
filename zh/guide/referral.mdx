# Owlyfi 邀请分佣系统

分享邀请码或邀请链接，邀请好友使用 Owly。好友通过纳入结算的交易账户产生 Builder 手续费后，你可以获得直接（L1）返佣；好友邀请的用户还可以为你带来间接（L2）返佣。被邀请用户可按适用规则享有一段时间的平台交易手续费折扣。

## 两级邀请关系

假设 A 邀请 B，B 再邀请 C：

| 产生手续费的用户 | 返佣接收者 | 计算比例 |
| :--- | :--- | :--- |
| B | A，获得 L1 返佣 | A 所在等级的 L1 比例 |
| C | B，获得 L1 返佣 | B 所在等级的 L1 比例 |
| C | A，获得 L2 返佣 | A 所在等级的 L2 比例 |

系统只结算 L1 和 L2 两级返佣。每位接收者使用自己的适用等级比例，C 的手续费折扣则由直接邀请人 B 的等级规则决定。

## 等级与返佣结构

邀请系统支持 Normal、Advanced 和 VIP 等级。以下为默认规则，实际生效值可由平台配置调整：

| 等级 | 直接邀请累计手续费门槛 | L1 返佣 | L2 返佣 | 好友手续费减免 | 折扣期限 | 直接邀请名额 |
| :--- | :--- | :--- | :--- | :--- | :--- | :--- |
| Normal | $0 | 30% | 5% | 5% | 14 天 | 5 人 |
| Advanced | $10 | 35% | 10% | 10% | 14 天 | 20 人 |
| VIP | $500 | 40% | 15% | 15% | 14 天 | 不限 |

<Note>
表中数值来自等级初始化配置，不代表所有环境当前生效的活动规则。请在**邀请分佣**页面查看自己的当前等级、邀请名额、可提现奖励和返佣记录。
</Note>

自动等级评估依据**已激活的直接邀请用户（L1）在返佣记录中累计的 Builder 手续费**，不包含 L2 手续费，也不按交易量或邀请人数评定。系统在结算后重新评估等级，后续结算使用更新后的适用比例；已结算奖励不会因升档自动重算。部分账户可能适用平台指定等级或单独调整的邀请名额。

直接邀请关系绑定后即占用邀请名额，尚未交易的好友也计入；间接邀请不占用你的直接邀请名额。

## 返佣计算基数

平台 Builder 手续费随策略而不同，策略基础费率为 **2–10 bps（0.02%–0.1%）**，具体以所选策略的 Builder 费率配置为准。相同交易量在不同策略下可能产生不同的手续费和返佣金额；符合条件的邀请折扣也会影响实际手续费。

返佣按**纳入结算的成交记录中实际收取的 Builder 手续费 × 接收者适用的返佣比例**计算。手续费基数来自被邀请用户当前有效、纳入结算的交易子账户；不能将其钱包在其他账户或平台上的全部交易视为可返佣交易。

好友支付的手续费降低后，返佣基数也会随之降低。Hyperliquid 交易所手续费、资金费和网络费用不属于该 Builder 手续费基数。

## 好友折扣说明

绑定邀请关系时，系统按直接邀请人的适用等级规则确定折扣到期时间，并从**绑定时刻**开始计时，无需等待首次交易。默认期限为 14 天，实际以绑定时适用配置为准。该折扣期限与浏览器保存邀请码的归因期限是两回事。

- 折扣期内，符合条件且由 Owly 管理费率的策略可以自动应用较低的 Builder 手续费。
- 折扣比例取决于邀请人当前适用的等级配置，并非一定锁定为注册时的比例。
- 邀请人升档不会自动延长已确定的折扣到期时间；折扣到期本身也不会解除邀请关系或终止返佣。
- 折扣通过减少交易时收取的费用体现，不会生成一笔需要好友单独提现的现金返还。
- 使用第三方 Builder 或保留独立低费率的策略不会被统一折扣规则覆盖，请在交易前确认实际费率。

折扣按所选策略的适用基础费率计算。例如，假设某策略的基础 Builder 费率为 **5.5 bps（0.055%）**，好友手续费减免为 5%，则折扣后的理论费率为 `5.5 × (1 − 5%) = 5.225 bps`。此处的 5.5 bps 仅为示例，实际策略基础费率在 2–10 bps 范围内，取决于具体策略配置。实际订单费率还会按交易接口支持的精度向上取整，返佣始终以实际成交手续费为准。

有关实际交易费与 Builder 授权上限的区别，请参阅[费用结构](/zh/faq/fees)。

## 邀请归因逻辑

Owly 在注册前采用**同一浏览器内的首次接触归因**：

1. 访问邀请码格式有效的邀请链接后，首个邀请码保存在浏览器 Cookie 中，最长保留 **30 天**。邀请码是否存在及是否仍有名额，在注册或绑定时校验。
2. 该 Cookie 有效期间，后续邀请链接不会覆盖它；已登录用户访问邀请链接也不会更换现有邀请人。
3. 注册时尝试使用保存的邀请码。后台会校验邀请码及剩余名额；携带无效或已满额邀请码的请求会被拒绝。当前页面在自动使用邀请码失败后会提示错误，并尝试不带邀请码继续注册；注册成功不等于邀请关系已绑定，可在邀请分佣页面确认邀请人。

Cookie 不等于永久账户绑定：清除 Cookie、到期或更换浏览器、设备后，原先保存的归因可能丢失。账户一旦已有邀请人，普通绑定流程不允许更换；如果注册时没有绑定邀请人，符合条件的用户可以在邀请分佣页面补填一次邀请码。

邀请码由 **4–16 位字母、数字、下划线或连字符**组成，匹配时不区分大小写。绑定还需通过邀请码有效性、剩余邀请名额和邀请资格检查。

## 结算与提现

系统通过定时任务拉取符合条件的成交手续费，按各交易子账户尚未结算的区间计算奖励。成功结算时，奖励记录与可用返佣余额一并更新；同一已成功结算区间不会因任务重试重复发放。

结算会预留数据同步延迟，记录出现的时间受任务调度、账户结算状态和上游数据可用性影响。成交后不会立即生成可提现返佣，接口暂时失败时需等待后续成功结算。

邀请关系可能先处于 `pending` 状态，待记录到符合条件且产生手续费的交易活动后再激活。邀请分佣页面分别展示邀请用户、已交易用户、返佣记录和提现历史。

### 历史交易与结算时间

- 新交易账户首次纳入结算时会先建立结算起点，不会自动补发此前全部历史交易的返佣。补绑邀请码也不代表既往交易一定可追溯返佣。
- 处于待对账状态的历史账户，需要先完成对账才能继续结算；相关历史奖励不会自动补发。
- 返佣记录中的**结算时间**是奖励实际结算入账的时间。结算日期是任务的记账日期，不能据此认定全部手续费都发生在该日，也不能将记录创建时间当作结算时间；历史记录缺少结算时间时以页面显示为准。

### 如何提现

1. 打开**邀请分佣**页面，查看可提现返佣余额。
2. 输入不超过该余额的金额。当前提现表单要求至少 **1 USDC**，实际适用规则可能要求更高的最低金额。
3. 提交申请。申请金额会先从可用返佣余额中扣除，进入后续处理流程。
4. 在提现历史中跟踪结果，核对最终状态和交易凭证。

| 状态 | 含义 |
| :--- | :--- |
| `pending` | 已提交，等待审核 |
| `approved` | 已批准，等待处理 |
| `processing` | 正在处理 |
| `completed` | 已记录为完成，并附有交易凭证 |
| `rejected` / `failed` | 审核拒绝或处理失败，申请金额退回可用返佣余额；原因见记录详情 |

<Note>
提交申请不等于立即完成链上转账。请以提现记录确认结果，本文不承诺固定到账时间。
</Note>

## 分佣计算示例

假设 A、B 均适用 Normal 默认比例，A 邀请 B，B 邀请 C。本例假设策略的**实际成交 Builder 费率为 5.5 bps（0.055%）**，即已考虑适用折扣及费率取整后的实际费率：

1. B 成交 10,000 USDC，实际 Builder 手续费为 `10,000 × 0.055% = 5.50 USDC`，A 获得 L1 返佣：`5.50 × 30% = 1.65 USDC`。
2. C 成交 20,000 USDC，实际 Builder 手续费为 `20,000 × 0.055% = 11.00 USDC`，B 获得 L1 返佣：`11.00 × 30% = 3.30 USDC`；A 获得 L2 返佣：`11.00 × 5% = 0.55 USDC`。
3. A 本次合计获得 `1.65 + 0.55 = 2.20 USDC`。C 的同一笔手续费分别作为 B 的 L1 和 A 的 L2 计算基数。

5.5 bps 是本例假设的费率，不代表所有策略统一收取该费率；示例返佣比例也不代表当前等级规则。实际金额请以适用规则和已结算返佣记录为准。

## 参与条件

系统拒绝自我邀请和循环邀请关系。邀请码也受使用次数限制，除非适用等级或账户名额另有安排。请勿使用虚假账户或人为制造的活动绕过邀请规则。
