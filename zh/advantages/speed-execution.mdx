Owly 将策略操作提交给 Hyperliquid，并在执行结果可用时更新账户状态。复制决策、交易所接受、成交和组合更新是不同阶段。

## 影响执行的因素

| 阶段 | 影响因素 |
| --- | --- |
| **观察来源** | 数据时效和来源市场活动 |
| **策略决策** | 账户状态、跟单比例、启用交易所、币种过滤和风险设置 |
| **提交委托** | 授权有效期、最低委托额、抵押品和交易所规则 |
| **成交** | 订单类型、价格、流动性、部分成交和行情变化 |
| **界面更新** | WebSocket 连接、API 可用性及缓存或刷新数据 |

提交后，委托可能保持挂单、部分成交或被拒绝。启动请求成功不代表来源的全部仓位已经复制完成。

## 复制与同步

跟单设置包含定期仓位、现货、杠杆和可选的挂单同步，各自有启用状态及时间间隔。同步周期不等于端到端执行保证；LeverAcc 不支持复制挂单。

网格机器人按自己的周期校准网格，其行为及账户条件见[网格机器人](/zh/guide/grid-bot)。

## 核对结果

1. 检查机器人当前状态及错误信息。
2. 查看实际委托和成交，包括部分成交或拒单。
3. 比较来源前先确认市场和账户统计范围一致。
4. 停止或关闭后，检查剩余委托、持仓和清理状态。

当前实现不能提供固定延迟或滑点保证，结果受行情和上游服务可用性影响。执行与预期不符时，参见[故障排除](/zh/faq/troubleshooting)。

团队的异步 Hyperliquid SDK 见 [async-hyperliquid](https://github.com/owlyfi/async-hyperliquid)。SDK 基准只说明特定测试条件，不能当作用户交易的延迟承诺。
