Owly는 Hyperliquid에 전략 작업을 제출하고 실행 결과가 나오면 계정 상태를 새로 고칩니다. 복사, 교환 승인, 채우기 및 포트폴리오 업데이트는 별도의 단계입니다.

## 실행에 영향을 미치는 것

| 무대 | 무엇이 영향을 미칠 수 있나요? |
| --- | --- |
| **출처 관찰** | 데이터 신선도 및 소스의 시장 활동 |
| **전략 결정** | 계정 상태, 복사 비율, 활성화된 장소, 코인 필터 및 위험 설정 |
| **주문 제출** | 승인 유효성, 최소 주문 규모, 담보 및 교환 규칙 |
| **채우기** | 주문 유형, 가격, 유동성, 부분 체결 및 시장 움직임 |
| **디스플레이 업데이트** | WebSocket 연결, API 가용성, 캐시되거나 새로 고쳐진 데이터 |

제출된 주문은 진행 중인 상태로 유지되거나, 부분적으로 작성되거나, 거부될 수 있습니다. 성공적인 시작 요청은 전략 요청이 수락되었음을 의미하며 모든 원본 트레이더의 포지션가 이미 복사되었다는 의미는 아닙니다.

## 복사 및 동기화

복사 설정에는 주기적인 위치, 현물, 레버리지 및 선택적인 보류 주문 동기화가 포함됩니다. 각각에는 고유한 활성화 상태와 간격이 있습니다. 동기화 간격은 종단 간 실행을 보장하지 않습니다. LeverAcc는 보류 주문 복사를 지원하지 않습니다.

그리드 봇은 구성된 그리드를 자체 간격으로 조정합니다. 동작 및 계정 요구 사항은 [Grid Bot](/ko/guide/grid-bot)에 설명되어 있습니다.

## 결과 확인

1. 봇의 현재 상태와 보고된 오류를 확인하세요.
2. 부분 주문 또는 거부된 주문을 포함하여 실제 주문과 체결을 검사합니다.
3. 소스와의 차이를 판단하기 전에 동일한 시장 및 계정 범위를 비교하십시오.
4. 중지 또는 종료 후 잔여 주문, 포지션, 정리 상태 등을 점검합니다.

Owly의 소스 구현은 고정된 대기 시간이나 미끄러짐을 보장하지 않습니다. 시장 상황과 업스트림 가용성이 결과에 영향을 미칩니다. 실행이 예상과 다른 경우 [문제 해결](/ko/faq/troubleshooting)를 참조하세요.

팀의 비동기 Hyperliquid SDK에 대해서는 [async-hyperliquid](https://github.com/owlyfi/async-hyperliquid)를 참조하세요. SDK 벤치마크는 자체 테스트 조건을 설명하며 보장된 사용자 거래 지연 시간으로 취급되어서는 안 됩니다.
