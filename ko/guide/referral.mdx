# Owlyfi 추천인 제도

추천 코드나 링크를 공유해 Owly에 친구를 초대하세요. 초대한 친구의 정산 대상 거래 계정에서 빌더 수수료가 발생하면 직접 추천 보상(L1)을 받을 수 있습니다. 그 친구가 초대한 사용자로부터 간접 추천 보상(L2)을 받을 수도 있습니다. 초대받은 사용자는 적용 규칙에 따라 일정 기간 플랫폼 거래 수수료 할인을 받을 수 있습니다.

## 직접 추천과 간접 추천

A가 B를 초대하고 B가 C를 초대한다고 가정합니다.

| 수수료를 낸 사용자 | 보상 수령인 | 적용 보상률 |
| :--- | :--- | :--- |
| B | A가 L1 보상을 받음 | A 등급의 L1 보상률 |
| C | B가 L1 보상을 받음 | B 등급의 L1 보상률 |
| C | A가 L2 보상을 받음 | A 등급의 L2 보상률 |

시스템은 L1과 L2 보상만 정산합니다. 각 수령인에게는 본인의 등급에 해당하는 보상률이 적용됩니다. C에게 적용되는 수수료 할인율은 직접 초대한 B의 등급과 관계없이 5%입니다.

## 추천 등급 및 보상

추천 등급은 일반, 고급, VIP입니다. 아래는 기본 규칙이며, 실제 적용 값은 플랫폼 설정에 따라 달라질 수 있습니다.

| 등급 | 직접 추천 누적 수수료 기준 | L1 보상 | L2 보상 | 피추천인 수수료 할인 | 할인 기간 | 직접 초대 한도 |
| :--- | :--- | :--- | :--- | :--- | :--- | :--- |
| 일반 | $0 | 30% | 2% | 5% | 14일 | 5명 |
| 고급 | $10 | 35% | 3% | 5% | 14일 | 20명 |
| VIP | $500 | 40% | 5% | 5% | 14일 | 제한 없음 |

<Note>
표의 할인 기간과 초대 한도는 기본값이며 플랫폼 설정에 따라 달라질 수 있습니다. **추천인** 페이지에서 현재 등급, 초대 한도, 출금 가능 보상 및 보상 내역을 확인하세요.
</Note>

자동 등급 평가에는 **활성 직접 추천(L1)의 보상 내역에 기록된 누적 빌더 수수료**가 사용됩니다. L2 수수료, 거래량, 초대 수는 등급 산정에 사용되지 않습니다. 정산 후 등급을 다시 평가하며, 이후 정산에는 갱신된 보상률을 적용합니다. 등급이 바뀌어도 이미 정산된 보상은 자동으로 다시 계산하지 않습니다. 일부 계정에는 등급이 별도로 지정되거나 초대 한도가 조정될 수 있습니다.

직접 초대한 사용자가 아직 거래하지 않았더라도 추천 관계를 등록하면 직접 초대 한도에서 한 자리를 사용합니다. 간접 초대는 내 직접 초대 한도에 포함되지 않습니다.

## 보상 계산 기준

플랫폼 빌더 수수료는 선택한 전략의 수수료 설정에 따라 기본 **2–10 bps(0.02%–0.1%)**입니다. 거래량이 같더라도 전략별로 수수료와 추천 보상이 달라질 수 있습니다. 추천 할인도 실제 납부 수수료에 영향을 줍니다.

보상은 **정산 대상 거래 기간에 실제 부과된 빌더 수수료 × 수령인에게 적용되는 보상률**입니다. 초대받은 사용자의 현재 활성 거래 하위 계정 중 정산에 포함된 계정의 수수료만 사용합니다. 해당 지갑으로 다른 계정이나 플랫폼에서 한 거래까지 모두 적용된다고 가정하지 마세요.

초대받은 사용자가 낸 수수료가 줄면 보상 계산의 기준 금액도 줄어듭니다. Hyperliquid 거래소 수수료, 펀딩비, 네트워크 비용은 빌더 수수료 기준에 포함되지 않습니다.

## 피추천인 할인 적용 방식

추천 관계를 등록하면 직접 초대한 사람의 등급에 적용되는 규칙에 따라 할인 만료 시점을 정합니다. 할인은 첫 거래를 기다리지 않고 **추천 관계가 등록되는 즉시** 시작됩니다. 기본 기간은 14일이며 실제 기간은 등록 시점의 설정에 따릅니다. 브라우저에 추천 정보를 저장하는 기간은 이와 별개입니다.

- 할인 기간에 지원되는 Owly 관리 전략은 인하된 빌더 수수료를 자동으로 적용할 수 있습니다.
- 모든 기본 초대 등급에 동일하게 **해당 빌더 수수료의 5% 할인**이 적용됩니다. 초대자의 등급이 올라가도 할인율은 늘어나지 않습니다.
- 초대자의 등급이 올라가도 기존 할인 만료 시점은 자동으로 연장되지 않습니다. 할인이 만료되어도 추천 관계나 추천 보상이 종료되지는 않습니다.
- 할인은 청구되는 거래 수수료를 줄입니다. 초대받은 사용자가 별도로 출금해야 하는 현금 리베이트는 적립되지 않습니다.
- 타사 빌더를 사용하거나 기존의 독립적인 낮은 수수료율을 유지하는 전략에는 표준 할인 규칙을 덮어쓰지 않습니다. 거래 전에 적용되는 수수료를 확인하세요.

할인은 선택한 전략의 기본 수수료에 적용됩니다. 기본 빌더 수수료가 **5.5 bps(0.055%)**인 전략에서 피추천인이 5%를 할인받는다고 가정하면, 계산상 할인 요율은 `5.5 × (1 − 5%) = 5.225 bps`입니다. 5.5 bps는 예시이며 실제 전략 기본 요율은 설정에 따라 2–10 bps입니다. 주문과 함께 제출하는 요율은 거래 인터페이스가 지원하는 정밀도에 맞춰 올림합니다. 보상 계산에는 항상 체결에 기록된 실제 수수료를 사용합니다.

거래 수수료와 빌더 수수료 승인 한도의 차이는 [수수료 구조](/ko/faq/fees)를 참조하세요.

## 추천 코드 적용

Owly는 가입 전 **같은 브라우저에서 처음 접한 추천 코드**를 사용합니다.

1. 올바른 형식의 코드가 포함된 추천 링크를 열면 첫 코드를 브라우저 쿠키에 최대 **30일간** 저장합니다. 코드가 실제로 존재하는지, 사용할 수 있는 초대 한도가 남아 있는지는 가입하거나 추천 관계를 등록할 때 확인합니다.
2. 쿠키가 유효한 동안 나중에 연 추천 링크는 기존 코드를 덮어쓰지 않습니다. 이미 로그인한 사용자의 기존 추천인도 변경되지 않습니다.
3. 가입 시 저장된 코드의 적용을 시도합니다. 백엔드는 코드와 남은 초대 한도를 확인하고, 코드가 유효하지 않거나 한도가 소진되면 요청을 거부합니다. 코드를 적용한 자동 가입에 실패하면 현재 페이지에 오류가 표시되며, 코드 없이 가입을 다시 시도합니다. 가입 성공만으로 추천 관계가 등록되었다고 볼 수는 없습니다. 추천인 페이지에서 내 추천인을 확인하세요.

쿠키에 저장된 코드는 계정에 영구적으로 등록된 추천 관계가 아닙니다. 쿠키를 지우거나 쿠키가 만료되거나 다른 브라우저 또는 기기를 사용하면 저장된 추천 정보를 사용할 수 없습니다. 계정에 추천인이 등록된 후에는 일반 절차로 추천인을 바꿀 수 없습니다. 가입할 때 추천인이 적용되지 않았다면 자격 요건을 충족하는 사용자가 추천인 페이지에서 코드를 한 번 입력할 수 있습니다.

추천 코드는 **영문자, 숫자, 밑줄, 하이픈으로 구성된 4–16자**이며 대소문자를 구분하지 않습니다. 코드를 등록하려면 코드가 유효하고 초대 한도가 남아 있어야 하며 추천 자격 요건을 충족해야 합니다.

## 보상 및 정산

정기 작업은 정산 대상 거래 수수료를 조회하고 거래 하위 계정별 미정산 기간의 보상을 계산합니다. 정산에 성공하면 보상 내역과 출금 가능 보상 잔액이 함께 갱신됩니다. 작업을 다시 시도해도 정산에 이미 성공한 기간의 보상은 중복 지급되지 않습니다.

데이터가 동기화되기까지 시간이 걸릴 수 있습니다. 작업 일정, 계정별 정산 상태, 상위 데이터 제공처의 가용성에 따라 내역 표시 시점이 달라집니다. 거래 직후에 출금 가능한 보상이 생기지는 않습니다. 일시적인 API 오류가 발생한 경우 이후 정산이 성공해야 보상이 반영됩니다.

수수료가 발생한 적격 활동이 기록되기 전까지 초대 상태가 `pending`으로 남을 수 있습니다. 추천인 페이지에서는 초대된 사용자, 거래한 사용자, 보상 내역 및 출금 내역을 구분해 표시합니다.

### 과거 거래와 정산 시점

- 새 거래 계정의 첫 정산은 정산 시작점을 설정합니다. 그 이전의 모든 거래에 대해 자동으로 보상이 지급되지는 않습니다. 추천 코드를 나중에 등록해도 보상의 소급 지급이 보장되지는 않습니다.
- 대사가 필요한 기존 계정은 대사가 완료되어야 정산을 계속할 수 있습니다. 과거 보상을 자동으로 소급 반영하지는 않습니다.
- 보상 내역의 **정산 시각**은 보상이 실제로 정산되어 잔액에 반영된 시각입니다. 정산일은 작업의 회계 기준일이므로 기초 수수료가 모두 해당 날짜에 발생했다는 뜻은 아닙니다. 내역 생성 시각도 정산 시각과 다릅니다. 과거 내역에는 정산 시각이 없을 수 있으므로 페이지의 표시를 기준으로 확인하세요.

### 출금

1. **추천인** 페이지를 열고 출금 가능 보상 잔액을 확인합니다.
2. 잔액 범위 내에서 출금 금액을 입력합니다. 현재 출금 양식의 최소 금액은 **1 USDC**이며, 적용되는 출금 규칙에 따라 더 높은 최소 금액이 요구될 수 있습니다.
3. 요청을 제출합니다. 처리 중에는 요청 금액이 출금 가능 보상 잔액에서 차감됩니다.
4. 출금 내역에서 요청을 조회하고 최종 상태와 거래 참조 정보를 확인합니다.

| 상태 | 의미 |
| :--- | :--- |
| `pending` | 검토를 위해 제출됨 |
| `approved` | 처리 승인됨 |
| `processing` | 처리 중 |
| `completed` | 완료로 기록되었으며 거래 참조 정보가 있음 |
| `rejected` / `failed` | 검토에서 거부되었거나 처리에 실패함. 요청 금액은 출금 가능 보상 잔액으로 반환되며, 내역에서 사유를 확인할 수 있음 |

<Note>
요청을 제출해도 온체인 전송이 즉시 이루어지지는 않습니다. 출금 내역에서 결과를 확인하세요. 처리 시간은 일정하지 않습니다.
</Note>

## 보상 계산 예시

A와 B 모두 기본 일반 등급 보상률을 적용받고 A가 B를, B가 C를 초대했다고 가정합니다. 아래 예시에서 할인 및 수수료 반올림을 반영한 체결의 **실제 빌더 수수료 요율은 5.5 bps(0.055%)**입니다.

1. B가 10,000 USDC를 거래하면 실제 빌더 수수료는 `10,000 × 0.055% = 5.50 USDC`입니다. A의 L1 보상은 `5.50 × 30% = 1.65 USDC`입니다.
2. C가 20,000 USDC를 거래하면 실제 빌더 수수료는 `20,000 × 0.055% = 11.00 USDC`입니다. B의 L1 보상은 `11.00 × 30% = 3.30 USDC`이고, A의 L2 보상은 `11.00 × 2% = 0.22 USDC`입니다.
3. A가 받는 총 보상은 `1.65 + 0.22 = 1.87 USDC`입니다. C가 낸 동일한 수수료를 기준으로 B의 L1 보상과 A의 L2 보상을 각각 계산합니다.

5.5 bps는 예시에 사용한 가정이며 전략마다 요율이 다를 수 있습니다. 예시의 보상률도 현재 등급 정책을 확정하지 않습니다. 실제 보상은 적용 규칙과 정산된 보상 내역을 확인하세요.

## 추천 자격

본인을 추천하거나 추천 관계가 고리를 이루는 경우 등록이 거부됩니다. 등급 또는 계정에 적용되는 한도 규칙에서 예외를 허용하는 경우를 제외하면 추천 코드의 사용 횟수는 제한됩니다. 허위 계정이나 인위적인 활동으로 추천 규칙을 우회하지 마세요.
