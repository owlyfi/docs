Owly를 사용하면 자산 소유자가 선택된 거래 권한을 가진 관리자를 추가할 수 있습니다. **관리자 권한은 나중에 추가된 계정을 포함하여 소유자의 모든 활성 거래 계정에 적용됩니다.** 하나의 하위 계정에 대한 별도의 할당이 아니라 소유자-관리자 관계입니다.

## 계정 준비

[Owly](https://app.owly.fi/accounts)에 자산 소유자로 로그인합니다. 일반 거래 계좌의 경우 [API 지갑 설정](/ko/guide/quick-start)을 사용하세요. 아래 설명에 따라 기본 Hyperliquid 하위 계정을 추가할 수도 있습니다. Owly의 공유 계정 제한과 Hyperliquid의 기본 자격 규칙은 별개입니다. [계정 유형](/ko/guide/account-types)을 참조하세요.

### 기본 Hyperliquid 하위 계정 추가

1. 기본 하위 계정을 소유하거나 생성할 Hyperliquid 마스터 지갑으로 로그인하세요.
2. 계정 관리를 열고 **서브 계정 만들기**를 선택한 다음 **Hyperliquid 서브 계정**를 선택하세요.
3. 기존 하위 계정을 선택하세요. 자격이 있는 경우 동일한 양식에서 **하위 계정 만들기**를 선택하고 최대 16자의 고유한 이름을 입력한 후 승인 및 생성 프롬프트를 따를 수 있습니다. Owly는 먼저 이 흐름에 필요한 일반 API 지갑 승인을 준비하거나 재사용합니다. 계속하기 전에 지갑 주소와 결과를 확인하세요.
4. 생성이 확인되지 않은 경우, 서브 계정 목록을 새로고침하여 원래 시도를 확인한 후 다시 생성하세요.
5. 계정의 표시 이름을 입력하고 계속하세요. 필요한 통합 계정 활성화, 전용 API 지갑 승인, 마스터 지갑을 통한 빌더 수수료 승인을 검토하고 서명하세요.
6. 완료를 기다린 후 선택한 거래 계좌 주소를 확인하세요. 개인 키를 입력하거나 복사하지 않습니다.

[Hyperliquid](https://app.hyperliquid.xyz/subAccounts)에서 적합한 기본 하위 계정을 만든 다음 Owly에서 선택할 수도 있습니다. 기존 기본 하위 계정은 계속 지원됩니다. 레거시 Owly 관리 지갑은 계정 유형이 다릅니다. 해당 지갑에서는 신규 생성, 신규 봇 설정, 봇 재시작이 비활성화됩니다.

<Note>
기본 하위 계정에는 자체 개인 키가 없습니다. 마스터 지갑은 API 지갑을 승인합니다. Owly는 공유 논스 충돌을 줄이기 위해 각 가져오기에 대해 전용 API 지갑을 생성합니다. 이는 Hyperliquid 프로토콜 수준에서 에이전트를 하나의 하위 계정으로 제한하지 않습니다.
</Note>

## 관리자 추가

관리자는 EVM 주소를 가진 등록된 Owly 사용자여야 합니다. 본인을 추가하거나 동일한 관리자를 두 번 추가할 수 없습니다. 각 소유자는 **최대 20 관리자**를 추가할 수 있습니다.

1. 계정 관리에서 **관리자 계정**을 찾아 **관리자 추가**를 선택하세요.
2. 관리자가 등록한 지갑 주소와 선택적으로 닉네임을 입력하세요.
3. **View**, **Start Bot** 및 **Stop Bot** 권한을 검토하세요. 세 가지 모두 기본적으로 선택됩니다. 부여하려는 권한만 유지하세요.
4. 확인하세요. 관리자는 **관리 서브 계정**을 이용해 해당 권한에 따라 귀하의 계정에 접근할 수 있습니다.

<Warning>
이는 향후 추가를 포함하여 활성 계정 전체에 대한 액세스 권한을 부여합니다. 확인하기 전에 전체 소유자 수준 범위를 검토하세요. 전용 거래 하위 계정은 해당 하위 계정에 특정한 관리자 권한을 부여하지 않습니다.
</Warning>

## 권한

| 권한 | 허용되는 것 |
| --- | --- |
| **보기 (`VIEW`)** | 지원되는 관리 보기를 통해 계정 및 전략 정보를 확인하세요. |
| **봇 시작 (`START`)** | 지원되는 봇 시작 또는 다시 시작 |
| **봇 중지 (`STOP`)** | 봇을 중지하거나 종료 및 정리를 요청하세요. |

봇 구성 변경은 시작/중지 권한 확인을 사용합니다. 별도의 관리자 구성 권한 스위치가 없습니다. 관리자 권한은 출금, 계정 소유권/설정 수정, 다른 관리자 추가 등 소유자 작업을 부여하지 않습니다. 계정 유형 제한 및 지갑 인증은 계속 적용됩니다.

API 지갑은 승인된 거래 행위에 서명합니다. 자산 소유자는 외부 자금 조달 및 인출을 위해 자금 지갑 또는 마스터 지갑 서명 역할을 유지합니다. 유출된 API 지갑은 여전히 ​​악의적인 거래로 인해 손실을 입을 수 있습니다. LeverAcc 계정의 경우 LeverAcc를 통해 담보, 부채, 상환 및 프로토콜 인출을 관리합니다. 봇을 중지해도 대출금은 상환되지 않습니다.

## 거래 모니터링 및 중지

계정 관리 및 포트폴리오에서 계정 잔액, 포지션, 주문, 손익, 봇 상태를 검토하세요. 런타임 및 정리 상태와 표시된 수명 주기 상태를 확인하세요.

- **Stop** 자동 실행을 중지합니다. 자체적으로 기존 포지션을 종료하지는 않습니다.
- **Close/terminate**는 전략 종료 및 포지션/주문 정리를 요청합니다. 정리 결과와 실제 위치를 확인합니다. 모든 근접 시도가 성공한다고 가정하지 마십시오.
- 보류 중이거나 실패한 정리에는 후속 조치가 필요합니다. 결과를 확인할 때까지 남은 증거금 의무에 대한 자금을 계정에 유지하십시오.

## 관리자 변경 또는 제거

관리자 카드의 **Edit**을 사용하여 닉네임이나 권한을 업데이트하세요. 관리자에 대한 해당 소유자의 승인을 취소하려면 **Remove**를 사용하세요.

**관리자를 제거해도 봇 실행이 자동으로 중지되거나 포지션이 닫히거나 주문이 취소되거나 Hyperliquid API 지갑 승인이 취소되지는 않습니다.** 거래를 종료하려면 영향을 받는 각 봇을 직접 중지하거나 닫고 상태와 남은 노출을 확인하세요. 관리자 한 명을 삭제해도 다른 관리자의 액세스 권한은 취소되지 않습니다.

API 지갑이 손상될 수 있는 경우 영향을 받는 자동화를 중지하고 마스터 지갑을 사용하여 [Hyperliquid API 페이지](https://app.hyperliquid.xyz/API)에서 승인을 검토하세요. Owly의 계정 관리 흐름에 따라 교체를 승인하세요. 어시스턴트, 지원 또는 관리자에게 시드 문구나 개인 키를 보내지 마십시오.

  <Accordion title="하나의 거래 계좌에만 관리자를 지정할 수 있나요?">
    현재 관리자 관계에는 소유자의 활성 계정이 포함됩니다. 해당 소유자 아래 별도의 기본 하위 계정을 생성해도 권한이 하나의 계정으로 축소되지 않습니다.
  </Accordion>
  <Accordion title="관리자 추가에 실패한 이유는 무엇인가요?">

  </Accordion>
  <Accordion title="기본 하위 계정 생성이 불가능한 이유는 무엇인가요?">

  </Accordion>
  <Accordion title="관리자가 자금을 인출할 수 있나요?">
    Owly의 보기/시작/중지 권한은 철회, 이전 권한을 부여하지 않습니다. 소유자의 지갑과 계정의 프로토콜 규칙이 이러한 작업을 관리합니다.
  </Accordion>
